# LIAR ROOM 😈

Українська браузерна party game від **LemvoriLab**. Будь-хто може бути ведучим: Twitch, облікові записи та встановлення клієнта не потрібні.

**Стек:** Next.js App Router + React, Node.js custom server + Socket.IO, PostgreSQL 16. Один origin і один порт для UI, HTTP і сокетів.

## Що реалізовано

- Кімната з випадковим шестисимвольним кодом: один ведучий + рівно п’ятеро гравців.
- Гостьові ніки, запрошення посиланням, лобі, вилучення гравця ведучим у лобі.
- 5 раундів, 4 правдиві ролі та 1 випадковий брехун у кожному раунді.
- Ведучий бачить загадку; правдиві — правильну відповідь; брехун — хибну легенду.
- Одна підказка від 2 до 80 Unicode-символів; 120 секунд на підказки. Пряму відповідь сервер відхиляє.
- Підказки відкриваються разом або після таймера. 90 секунд на фінальну відповідь і одне звинувачення.
- Розкриття ролей, приріст очок, поточний рахунок, підсумок матчу з підтримкою нічиєї.
- Тренування для одного ведучого з п’ятьма ботами та заготовленими підказками. Це **не AI** й не реальні люди.
- 20 авторських коротких загадок у 5 темах + змішаний режим. У вузькій темі п’ята загадка повторюється після вичерпання 4 загадок.
- Адаптивний інтерфейс українською, оригінальні SVG-маски, клавіатурний фокус, приховування своєї ролі, режим ефіру для ведучого.
- PostgreSQL зберігає кімнати, підказки, ролі, результати та сесії. Перезапуск сервера не скидає матч.
- Перепідключення через секретний токен сесії, що зберігається в sessionStorage цієї вкладки. У БД зберігається тільки SHA-256 токена.
- Таймери та рахунок контролює сервер; зміни кімнати серіалізуються транзакціями з SELECT FOR UPDATE.

## Правила очок

| Учасник | Умова | Очки |
| --- | --- | --- |
| Брехун | Звинувачення хибне або ведучий не встиг | +150 |
| Кожен правдивий | Правильна відповідь на загадку | +100 |
| Ведучий | Правильна відповідь | +100 |
| Ведучий | Правильно викритий брехун | +100 |

Відповідь і звинувачення — одне остаточне рішення. Можна розв’язати загадку й звинуватити невинного: тоді правдиві та брехун отримають свої очки. Правильна відповідь без викриття не позбавляє брехуна очок. Після завершення таймера брехун отримує +150; інші — 0.

Ведучий лишається тим самим на 5 раундів. Новий матч — нова кімната. Спільного глобального рейтингу немає: ролі мають різні умови заробітку очок.

## Запуск через Docker — рекомендовано

Потрібен Docker з Compose.

1. Скопіюй .env.example у .env.
2. У .env зміни POSTGRES_PASSWORD на довгий випадковий пароль з URL-safe символів: літери, цифри, дефіс. Не використовуй стандартний приклад у публічному розгортанні.
3. Задай APP_ORIGIN — точну адресу, за якою відкривають гру, без завершального слеша. Локально: http://localhost:3000.
4. Запусти:

```bash
docker compose up --build -d
```

Відкрий http://localhost:3000. Натисни **Спробувати з ботами**, щоб перевірити гру самому. Для компанії створи звичайну кімнату та запроси п’ятьох.

```bash
docker compose logs -f game
docker compose down
```

Звичайний down зберігає дані у volume liar-data. Не додавай --volumes, якщо хочеш їх зберегти.

## Локальна розробка

Node.js 22+, npm та доступний PostgreSQL. Створи окрему БД liar_room і користувача для неї. В .env вкажи відповідний DATABASE_URL і APP_ORIGIN.

```bash
npm install
npm run dev
```

Схема з server/schema.sql створюється сервером під час запуску. База повинна існувати; користувачу потрібні права створювати таблиці. У продакшні можна застосувати схему окремо перед запуском і обмежити права runtime-користувача.

```bash
npm test
DATABASE_URL=postgres://liar:password@localhost:5432/liar_test npm run test:integration
npm run build
npx playwright install chromium
npm run test:browser
npm start
```

Інтеграційні тести запускай на **окремій тестовій БД**. Вони створюють кімнати, видаляють лише створені ними кімнати і перезапускають свій тестовий сервер.

Перший npm install створює package-lock.json; CI додає його до артефакту mvp-check-evidence. Початковий коміт не містить lock-файла, тому перше встановлення може обрати нові сумісні версії. Для відтворюваних збірок зафіксуй отриманий lock-файл та використовуй npm ci.

## Публічний сервер

Це довгоживучий Node.js сервер, тому звичайний serverless-хостинг лише для Next.js не підходить. Розмісти Docker Compose на VPS або на платформі з постійним процесом і підтримкою WebSocket.

- Направ домен через TLS reverse proxy на порт гри. Proxy має передавати WebSocket Upgrade та Connection.
- APP_ORIGIN має точно збігатися з origin у браузері, наприклад https://liar.example.com.
- PostgreSQL не відкривається зовні через Compose.
- Порт за замовчуванням — 3000. Параметр PORT у Compose змінює зовнішній порт, APP_ORIGIN потрібно оновити відповідно.
- GET /healthz перевіряє з’єднання з БД. GET /api/catalog повертає тільки публічні теми, без відповідей.
- Запускай **один процес/одну репліку** сервера: кімнати в БД, але присутність і доставки Socket.IO локальні. Для кількох реплік потрібні спільний адаптер Socket.IO, присутність та розподілені таймери.
- Сервер перевіряє Origin, обмежує розмір Socket.IO повідомлень, кількість дій і нових handshake. Ліміти локальні процесу; за proxy IP з’єднань може бути спільним. Для відкритого великого запуску налаштуй ліміти на reverse proxy.
- Забороняй публічне кешування Socket.IO та приватних знімків стану.
- Для інтернет-запуску додай операційний моніторинг, резервні копії БД і перевірку відновлення.
- Зовнішні Google Fonts необов’язкові: є системні fallback-шрифти.

## Дані й межі MVP

Кімната та всі її сесії видаляються після 24 годин від останньої зміни гри; cleanup проходить раз на хвилину. Ніки й підказки бачать учасники кімнати. Не вводь чутливі дані.

Кнопка «Вийти» від’єднує клієнта, зберігаючи токен у вкладці: повернися через «Профіль → Відновити поточну кімнату». «Забути сесію» видаляє локальний токен, після чого повернутися на зайняте місце неможливо. Ведучий може звільнити таке місце **лише в лобі**. Посеред матчу місця не підміняються: таймер завершує поточний раунд, а наступний потребує всіх учасників онлайн. Якщо ведучий пішов назавжди, створіть нову кімнату.

Відповіді порівнюються з визначеними синонімами без урахування регістру, пробілів, пунктуації та апострофа. Вільне семантичне оцінювання й розпізнавання довільних перефразувань не реалізовано.

Не реалізовано: голосовий чат, Twitch, акаунти, публічний matchmaking, скарги/модерація, реальні платежі, куплені права доступу, справжній AI ботів, міграції версій даних. Код публічний: уважний гравець може прочитати каталог загадок у репозиторії. Для змагань із призами потрібен непублічний каталог та ширша модель захисту.

## Перевірки

GitHub Actions запускає unit-тести, інтеграційні тести на PostgreSQL із реальними Socket.IO клієнтами, production build, HTTP smoke-check та Chromium-перевірки інтерфейсу на desktop/mobile. Скриншоти й trace доступні в артефакті browser-review. Перевіряються приховані ролі, серверні обмеження, гонка підказок, очки без повторного нарахування, перепідключення, відновлення після перезапуску, вилучення гравця та відхилення чужого Origin.

Проходження CI не замінює ручну перевірку в браузері на desktop і mobile. Статус конкретного запуску дивись у вкладці Actions.

## Структура

- app/ — Next.js UI, CSS і метадані.
- public/ — оригінальні SVG-ілюстрації.
- server/game.mjs — чиста логіка гри та персональні знімки.
- server/riddles.mjs — серверний каталог загадок.
- server/runtime.mjs — Socket.IO, PostgreSQL, сесії, таймери.
- server/index.mjs — спільний HTTP-сервер Next.js + Socket.IO.
- tests/ — unit та інтеграційні тести.
